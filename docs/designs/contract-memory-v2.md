# 合同记忆 v2：风险处置闭环

状态：代码及模拟验证；尚未部署到当前实验服务，未运行真实抽取或 judge。版本 contract-v2。

## 数据含义

|层级|业务含义|来源及生效|
|---|---|---|
|L0|真实业务证据、对话、读取、风险报告与处置事件|原始来源不可变|
|L1|历史处置案例；明确长期偏好声明|风险卡片保存反馈后即可作为本人同团队案例；声明尚未生效|
|L2|带条件的风险处置方法|两个不同合同空间或明确复用已有案例的指令；须确认|
|L3|审查原则、长期交付偏好、称呼与语气|明确长期声明或正式跨场景经验；须确认|

裸条款作为案例证据背景；助手建议、临时操作和确认流程说明不生成长期内容。原报告结论、用户选择、真实审批与执行状态分别保存。接受风险不是正式批准，要求修改不是修改已完成。

## 批复记录

保存反馈和 `contract_memory_outbox` 在同一个 SQLite 事务中写入。后台投递 `/v3/contract-memory/review-events`，验证用户、Team、Agent、Task 和控制凭据。事件 ID 对同一报告、风险、反馈版本稳定，重复投递不重复保存。同一合同版本、风险定义的重复报告不计作多个独立案例。

事件携带真实的反馈方式、备注、Actor、时间、报告与风险定义、文档版本及原文引用。模型只整理摘要与条件，不改写这些权威字段。待处理使旧处置退出参考；版本、历史事件继续保留。

仅已接入合同记忆且报告由 Memory provider 运行的反馈进入事件队列，普通 provider 保持原路径。UI 分别显示反馈已保存、同步待完成、处理案例已记录和提炼待确认。失败支持在风险卡片重试。

## 检索与业务展示

浏览器使用 `/api/artifacts/{aid}/risks/{rid}/precedents`。Agent 使用固定只读脚本 `runtime/scripts/recall_precedents.py`，访问 `/internal/contract-memory/precedents`。内部接口沿用会话凭据，校验本轮已启用合同记忆，用户/Team/Task 不由模型传入。

脚本命令经过插件字面量解析，不允许命令串联、Shell 展开、其他脚本和地址。普通 provider 不增加该权限。原通用 memory bridge 的 Task 限制保留。

检索跨本人同团队合同：先按范围与主题筛选最多20个候选，再用独立 case_relevance 阶段核对角色、当前标准、原文条件与项目限制。最多返回3条。角色相反直接排除；未知角色、项目限定或标准变化不能直接适用。风险编号相同不证明语义相同。

卡片显示历史处理、条件、差异、案例版本与可访问来源。来源先于推理检查，推理后和缓存命中时再次检查。当前风险标准按当前方案读取；原已保存报告不重写。个人案例不向其他成员开放，团队继续复用审核发布的 L2/L3。

每次合同调度和检索同步当前可访问文档/空间清单到受控 resources 接口；源文档替换或合同移除时，案例及其衍生经验退出有效视图。契约版本请求绕过旧 TDAI 注入缓存，code/chat 的默认缓存行为保留。

## 候选、人工保护及历史

提示词全文位于独立 Memory 仓库 `MemoryCore/src/contract-memory/prompts.ts`，按角色、职责、来源、类型、排除、工作流、冲突、结构、示例及成功标准编写。L2 正文目标80–160字，程序上限240；L3 单条正文上限80，完整条件另列，不截断限制。

不合格输出进入只读待复核记录，避免连带丢失有效候选。新版确认校验来源仍有效；针对正式内容的更新建议包含目标版本，确认前发生人工修改则返回409。人工内容只在用户明确确认更新时变更。忽略/删除用稳定来源标记抑制再生。个人称呼不能发布到团队。

v1 内容保留在历史页，退出 v2 检索、注入和提炼。只读 `/api/contract-memory/migration-preview` 检查旧反馈的状态、来源、权限、版本及映射；`migration-enqueue` 只接受预检通过的真实反馈 ID 和版本，复查后重建事件，默认不调用。旧摘要不能用来伪造批复。

## 验证与运行边界

已增加 Core 模拟管线、案例版本/撤回、偏好排除、跨用户/团队、源删除、相反角色、旧缓存测试；应用测试覆盖保存事务、同步失败/重试、权限与版本复核、迁移预检和只读凭据。卡片使用主题变量，真实浏览器离线检查浅/深色布局，证据见 `docs/evidence/contract-memory-v2`。

测试包新增 contract-v2 场景、结构化模型 Schema、后台只读表导出和操作手册；旧58用例保留用于旧分层对照。旧“条款事实就是L1”断言不用于新版，新的评分仍要求实际原文、报告、反馈和模型轨迹。任何无匹配、模糊候选或服务失败均停止相关步骤，不预灌金标。

本轮不启动真实抽取/评分，不重启现有服务，不自动迁移历史数据。测试包审查通过后，在隔离服务中构建并运行同模型的实际对照；Core 必须先升级，应用再升级，不能混用 v1 Core 与 v2 应用。
